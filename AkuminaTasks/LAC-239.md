## Business Goal

Keep the Resource Directory filtering workflow usable on tablet and phone layouts so users can reset filters without having to manually uncheck multiple options or switch to desktop.

## Plain-English Summary

The Resource Directory already has a working `Clear Filters` control in desktop view.

On iPad/tablet and phone/mobile layouts, the ticket reporter says that same control is missing. The filter UI still exists, but the reset action is not visible in responsive views, which makes the mobile experience incomplete and inconsistent with desktop.

## Acceptance Criteria

1. The Resource Directory shows a visible `Clear Filters` control on desktop, tablet, and phone layouts.
2. On tablet and phone layouts, the control is reachable within the responsive filter UI users actually interact with.
3. Clicking `Clear Filters` clears the search term and selected refiners just as it does on desktop.
4. Existing desktop filter behavior does not regress.
5. Existing mobile/tablet filter open/close behavior does not regress.

## Technical Understanding

Current behavior:

Jira reports that desktop shows the filter reset affordance, but tablet and phone views do not. The current Resource Directory template already renders a `button.ia-button-text.ak-clearfilter-js.court-clear-filters` inside `.ia-search-filter-actions`.

The shared custom script already binds a delegated click handler for `.court-clear-filters, .ak-clearfilter-js` and clears the search box, hidden `#siteSearch`, checked refiners, and URL state. That strongly suggests the broken area is presentation/layout in responsive view, not missing clear logic.

There is also a duplicate `tileview.html` under `src/js/widgets/GenericSearchListWidget/views`, which likely needs to stay in sync with the content template to avoid drift.

Expected behavior:

On tablet and phone layouts, users should still see and use a clear/reset control from the responsive filter experience, and it should trigger the same clearing logic already used on desktop.

Risk level:

Medium. The clear logic already exists, which reduces code risk, but responsive filter markup can be fragile and easy to regress across desktop/tablet/mobile breakpoints.

## Proposed Fix

Recommendation:

Use a dedicated mobile/tablet clear icon in the top search/view-controls row, positioned between the search bar and the grid/list view icons. Reduce the effective search width on smaller breakpoints to make room for the control.

Keep the existing delegated clear handler instead of creating a second clearing implementation.

Why this approach:

This matches the intended mobile UX: the clear action is promoted into the same compact toolbar users already use for search and view switching. The button already exists conceptually and the clear behavior already exists in JavaScript, so reusing that path minimizes risk and keeps desktop, tablet, and phone behavior aligned.

What could make this larger than expected:

If the mobile filter UI is generated or rearranged by Akumina after render, Scott may need a small JS enhancement to relocate or clone the clear control into the mobile filter container after load instead of relying on CSS alone.
