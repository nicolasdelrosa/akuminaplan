## Technical Understanding

Current behavior:

The current supported favorite UI is in grid view. The list view in `TileView.html` renders only icon, title, and description columns. It has no bookmark button in each row.

The user-provided screenshot confirms the current grid-view state: the star action is visible on the resource cards today and is the entry point for bookmark creation.

The user-provided list-view screenshot confirms the current table-like layout: the rows show icon, title, and description only, with no star action present.

The grid view in the same template already renders a `.court-tile-bookmark-btn`, and the page-level custom script binds click events for that class and routes them into `AddCourtResourceBookmark(...)`.

`AddCourtResourceBookmark(...)` currently looks up the link context by walking upward to `.court-resource-tile`, which works for grid tiles but not for list rows.

Expected behavior:

List view should expose the same star affordance as grid view and should reuse the same bookmark-trigger flow so behavior stays aligned across both views.

## Proposed Fix

Recommendation:

Add a bookmark/star button to each list-view row using the same `.court-tile-bookmark-btn` class and `data-title` / `data-url` attributes as grid view, then update `AddCourtResourceBookmark(...)` so it can resolve link context from either a grid tile or a list row and trigger the same bookmark flow.

Why this approach:

The existing event binding already targets `.court-tile-bookmark-btn`, so extending the list markup to reuse that class keeps one code path for both views. The main code-level gap identified so far is that the helper assumes grid tile structure when detecting `target="_blank"` and related link context.

What could make this larger than expected:

If "toggle favorite" means true persisted starred-state rendering with immediate visual sync across both views, there may be additional integration work with the Bookmark-Favorites widget or saved-state APIs beyond the current add-bookmark modal launch.

**UX/Design Review - Text Alignment Issue Identified (2026-03-20):**

**Problem:** Title and Description text in list view rows appears visually misaligned.

**Root Cause Analysis (CSS):**
1. Title column (nth-child 3) has `padding-left: 18px` applied
2. Description column (nth-child 4) lacks equivalent padding specification → text starts at different horizontal position
3. Both columns use implicit/middle vertical alignment instead of top alignment → text rows don't align horizontally
4. Inconsistent baseline positioning causes Title and Description to appear offset

**Recommended CSS Fixes:**
```css
/* Align Title and Description columns consistently */
.court-resources-widget .ia-people-results-list tbody td:nth-child(3),
.court-resources-widget .ia-people-results-list tbody td:nth-child(4) {
    vertical-align: top;      /* Align text to top of cell */
    padding-left: 16px;       /* Consistent left padding */
    padding-right: 16px;      /* Consistent right padding */
}

/* Ensure uniform row height and cell spacing */
.court-resources-widget .ia-people-results-list tbody td {
    padding-top: 12px;        /* Consistent top padding */
    padding-bottom: 12px;     /* Consistent bottom padding */
}
```

**Why This Works:**
- ✅ Symmetric padding (16px left/right) for both text columns
- ✅ Explicit `vertical-align: top` ensures text baseline aligns at top of cells
- ✅ Consistent vertical padding creates uniform row heights
- ✅ Follows standard data table UX patterns (text aligned top-left)

**Expected Improvement:**
After applying these CSS changes, Title and Description text will be perfectly aligned horizontally, creating a clean, professional table appearance with no visual offset.
